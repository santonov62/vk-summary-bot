# VK Summary Bot

Бот для ВКонтакте, который делает выжимку переписки с помощью модели NVIDIA Nemotron.

Бот работает от имени **сообщества ВКонтакте** и ничего не хранит: по команде он читает историю беседы через API
ВКонтакте, отправляет её модели и пишет сводку в тот же чат.

Зависимостей нет — нужен только Node.js 20+ (используется встроенный `fetch`).

## Настройка сообщества

1. Создайте сообщество (или возьмите своё): https://vk.com/groups_create.
2. **Управление → Сообщения**: включите сообщения сообщества.
3. **Управление → Сообщения → Настройки для бота**: включите «Возможности ботов» и
   «Разрешать добавлять сообщество в беседы».
4. **Управление → Работа с API → Ключи доступа**: создайте ключ с правом «Сообщения сообщества»
   и скопируйте его в `VK_GROUP_TOKEN`.
5. **Управление → Работа с API → Long Poll API**: включите Long Poll API (версия 5.199), на вкладке
   «Типы событий» отметьте «Входящее сообщение».
6. Добавьте сообщество в беседу (в беседе: «Добавить участника» → найти сообщество) и **назначьте его
   администратором беседы** — иначе оно не видит сообщения без упоминания и не может читать историю.

**Внимание:** ключ даёт доступ к сообщениям сообщества. Никому его не передавайте и не публикуйте файл `.env`.
Если ключ утёк — удалите его в разделе «Работа с API» и создайте новый.

## Ключ NVIDIA

Ключ берётся на https://build.nvidia.com (начинается с `nvapi-`). По умолчанию используется
`nvidia/nemotron-3.5-super-vl-120b-a12b` — она понимает картинки, поэтому `/ии` может отвечать про фото.
Можно указать другую модель Nemotron в `NVIDIA_MODEL`, например `nvidia/nemotron-3-ultra-550b-a55b`
или `nvidia/nemotron-3.5-lightning-30b-a3b`, но они картинки не понимают.
NVIDIA периодически снимает старые модели с поддержки — проверить связь и модель можно командой `npm run check`.

## Проверка настроек

```bash
npm run check
```

Проверяет ключ сообщества, настройки Long Poll, доступ к сообщениям и отвечает ли модель NVIDIA.

## Запуск

```bash
cp .env.example .env   # заполнить токены
npm start
```

## Запуск на сервере (VPS)

Нужен Linux-сервер с systemd (Ubuntu, Debian и т. п.), доступ по SSH под `root` и Node.js 20.6+:

```bash
# на сервере, если Node.js ещё нет (Ubuntu/Debian)
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt-get install -y nodejs rsync
```

Дальше — с вашего компьютера, из папки проекта:

```bash
./deploy/deploy.sh root@1.2.3.4
```

Или короче: `npm run deploy` — сервер берётся из `DEPLOY_HOST` в `.env` (другой можно указать так:
`DEPLOY_HOST=root@5.6.7.8 npm run deploy`). Лог бота с сервера: `npm run logs`.

Скрипт копирует бота в `/opt/vk-summary-bot` вместе с `.env`, создаёт системного пользователя `vkbot`
и запускает сервис `vk-summary-bot`. Тот же скрипт обновляет бота после изменений.

Бот должен работать только в одном месте: перед запуском на сервере остановите его на компьютере,
иначе на каждую команду придёт два ответа.

Полезные команды на сервере:

```bash
journalctl -u vk-summary-bot -f        # лог в реальном времени
systemctl restart vk-summary-bot       # перезапуск
systemctl stop vk-summary-bot          # остановка
```

## Автоматическое развёртывание (GitHub Actions)

Разработка ведётся в ветке `dev`. Когда в `main` что-то попадает, GitHub Actions сам разворачивает бота
на сервере (`.github/workflows/deploy.yml`).

Ветка `main` защищена: пушить в неё напрямую нельзя, изменения попадают туда только через pull request
из `dev`. Это проверяет `.github/workflows/main-source.yml`, а правило ветки делает проверку обязательной.

```bash
git checkout dev        # работаем в dev, коммитим и пушим сюда
git push
```

Чтобы выкатить на сервер, откройте pull request `dev → main`
(https://github.com/santonov62/vk-summary-bot/compare/main...dev), дождитесь проверки и нажмите
Merge pull request. После слияния подтяните `main` локально, если он нужен: `git pull origin main`.

Ход развёртывания и ошибки видны на вкладке Actions репозитория. Запустить развёртывание вручную можно там же:
Deploy → Run workflow.

Для работы нужны секреты репозитория (Settings → Secrets and variables → Actions → New repository secret):

| Секрет | Что в нём |
|---|---|
| `SSH_PRIVATE_KEY` | приватный SSH-ключ, которым Actions входит на сервер |
| `SSH_KNOWN_HOSTS` | отпечатки сервера (`ssh-keyscan 1.2.3.4`) |
| `ENV_FILE` | всё содержимое `.env`, включая `DEPLOY_HOST` |

Если поменяли `.env` — обновите секрет `ENV_FILE`, иначе при следующем развёртывании на сервер вернутся старые
настройки.

## Команды

Команды может отправить любой участник беседы, куда добавлено сообщество, а также любой, кто пишет сообществу
в личные сообщения. Команду можно отправить и с упоминанием: `@club123 /сводка`.

Чтобы бота не заспамили, команды в одном чате принимаются не чаще раза в `COMMAND_COOLDOWN_SEC` секунд
(по умолчанию 60, `0` — без ограничения). На пользователей из `ADMIN_IDS` ограничение не действует.

| Команда | Что делает |
|---|---|
| `/сводка` | выжимка за сегодня |
| `/сводка вчера` / `/сводка позавчера` | за вчера / позавчера |
| `/сводка неделя`, `/сводка месяц` | за 7 / 30 дней |
| `/сводка 6ч`, `/сводка 3д` | за последние N часов / дней |
| `/сводка 25.11`, `/сводка 20.11-25.11` | за дату / диапазон дат |
| `/ии вопрос` | ответ ИИ на любой вопрос |
| `/ии …` ответом на сообщение | вопрос про это сообщение, например `/ии переведи` |
| `/ии` с фото или ответом на фото | ответ про картинку (без текста — описание картинки) |
| `/чат вопрос` | вопрос по переписке чата за последние 7 дней: «кто обещал взять проектор?», «найди ссылку на магазин» |
| `/чат месяц вопрос` | то же за указанный период (периоды как в `/сводка`) |
| `/помощь` | справка |

Также работают `!сводка`, `/выжимка`, `/итоги`, `/summary`, а для вопросов — `/ai`, `/вопрос`, `/спроси`.
`/чат` читает историю так же, как `/сводка`, поэтому у них общая пауза `COMMAND_COOLDOWN_SEC`.
Вопросы к ИИ ограничены паузой `ASK_COOLDOWN_SEC` (по умолчанию 15 секунд на чат), отдельной от паузы сводок.

Сводка отправляется в тот же чат от имени сообщества — её видят все участники. Ответы бота помечаются 🤖
и не попадают в следующие сводки.

## Ограничения

- Бот видит только беседы, куда добавлено сообщество, и личные сообщения самого сообщества. Ваши личные диалоги
  он не читает.
- Сообщения, написанные до добавления сообщества в беседу, обычно недоступны — сводка будет только по тому,
  что сообщество успело увидеть.
- За один раз загружается не больше `MAX_MESSAGES` сообщений (по умолчанию 3000) — самые свежие за период.
- Длинная переписка автоматически разбивается на части, и выжимка собирается по частям.
- Ошибка `[9] Flood control` значит, что ВК временно ограничил отправку. Повторные запросы продлевают ограничение,
  поэтому бот перестаёт обрабатывать команды на 30 минут.
